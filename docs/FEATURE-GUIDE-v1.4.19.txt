FB 贴文数据采集 v1.4.19 — 贴文 ID 查找功能说明

一、安装版本
Windows 64 位使用 Setup.exe 或 MSI；ZIP 为便携版。
Mac M 系列芯片使用 arm64.dmg，Intel 使用 x86_64.dmg，要求 macOS 15 或以上。
升级前退出软件并备份数据，使用原电脑、原系统账号启动。跨电脑迁移请导入配置并重新授权。

二、贴文 ID 查找项目
项目页面新增项目时，类型选择“贴文 ID 查找项目”。填写 Google 表格链接，并选择已登录的抓取账号。
同一个 Google 表格中分别配置：
1. 专页列表：A1 为表头，A2 起填写候选专页链接，使用 profile.php?id=数字ID 或 /数字ID 格式。
2. 贴文id：A1 为表头，A2 起填写完整贴文数字 ID。先设置单元格为纯文本再粘贴，避免长数字被舍入。
3. 采集结果：独立输出分表，首次运行时自动创建；名称可自定义，但不能与两个输入分表相同。

软件逐个读取候选专页的当前账号可见贴文，精确核对贴文 ID 和作者 ID，不会只拼接链接就宣称匹配成功。
两个输入分表不会修改。结果分表 A–D 固定为查询贴文 ID、来源专页链接、来源专页名称、查找状态。
贴文内容、OCR、翻译、图片和音频等沿用现有采集流程，字段可从 E 列起自行映射。
已成功的 ID 下次跳过；未成功记录可再次运行重试，并写回原结果行。重复 ID 合并处理。
多个账号按候选专页轮询，本模式顺序查找。运行支持暂停与停止，停止后保留已成功写入的数据。

三、状态与限制
每个专页默认最多读取 100 页，可配置 1–1000 页。界面显示当前专页、页数和剩余 ID 数量。
达到上限、访问失败、内容不可见不等于贴文不存在；结果会区分未完成核实、未找到及已找到但采集失败。
遇到结果分表表头不兼容时会停止写入，请换一个新的结果分表名称，不要清空旧数据。
账号权限、Facebook 接口变化、网络、语言识别和翻译配额均会影响结果，建议先用少量 ID 实测。
配置支持导入、导出和复制，不携带账号凭据。不同电脑同时向同一结果分表写入没有分布式锁，请使用不同结果分表。

四、原有功能
继续支持贴文链接采集、按日期采集专页、可视化字段配置、行区间、账号轮询、OCR/音频识别与翻译、Google Drive 图片上传及组件环境检测。
未使用 Apple Developer ID 签名/公证；Mac 首次打开需按系统提示授权单个应用，不要全局关闭系统安全防护。
音频处理仍建议使用 1 路并发。安全审核报告仅保留本地，不随本次发布上传。
